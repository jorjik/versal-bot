Технічне завдання (ТЗ) на розробку Telegram-бота для нічного клубу "Версаль"
1. Загальний опис проєкту
Мета проєкту: створення Telegram-бота для автоматизації роботи з гостями нічного клубу, караоке та диско-залу.
Основні завдання бота:
Автоматизація запису в Guest List (безкоштовний вхід для дівчат до 20:00) з генерацією одноразових QR-кодів.
Надання гостям актуальної інформації (Афіша, Меню).
Прийом заявок на бронювання столів із демонстрацією схеми залу.
Збір бази контактів для подальшого маркетингу (розсилок).
2. Ролі користувачів
Система повинна передбачати 3 рівні доступу:
Гість (Клієнт): звичайний користувач бота.
Охорона/Хостес: персонал на вході, який має права на сканування та валідацію QR-кодів.
Адміністратор: повний доступ до налаштувань, розсилок, редагування контенту та перегляду статистики.
3. Функціонал для ролі "Гість" (Клієнтська частина)
Після команди /start бот вітається, збирає базові дані (Номер телефону через вбудовану кнопку Telegram request_contact для ідентифікації) і видає Головне меню з 4 кнопками (Inline або Reply клавіатура):
Кнопка 1: 📝 Guest List (Вхід до 20:00)
Логіка: Користувач натискає кнопку для запису на найближчу вечірку.
Умови: Бот перевіряє, чи не вичерпано ліміт місць (встановлюється адміністратором). Якщо місця є, користувач підтверджує запис.
Результат: Бот генерує унікальний QR-код (або штрих-код) та надсилає повідомлення: "Ваш квиток у Guest List! Покажіть цей QR-код охороні до 20:00. Увага: код діє лише на один вхід."
Кнопка 2: 📅 Афіша подій
Логіка: Виведення списку найближчих заходів (концерти, тематичні вечірки).
Формат: Картинка (постер) + опис (дата, час, запрошені артисти, вартість входу після 20:00 або без Guest List).
Кнопка 3: 🥂 Меню (Бар та Кухня)
Логіка: Надання гостю доступу до прейскуранта.
Формат: На вибір розробника — або відправка PDF-файлу меню.
Кнопка 4: 🛋 Бронювання столів
Логіка: Залишення заявки на резерв.
Процес:
Бот надсилає картинку зі схемою залу (зонування: караоке, диско, VIP).
Запитує в користувача бажану дату.
Запитує кількість осіб.
Запитує побажання (номер столу або зона).
Формує заявку і відправляє її Адміністратору. Користувачу пише: "Ваша заявка прийнята, адміністратор зв'яжеться з вами найближчим часом для підтвердження."
4. Функціонал для ролі "Охорона/Хостес" (Валідація на вході)
Цей функціонал має працювати максимально швидко, щоб не створювати чергу.
Інструмент: Вбудований сканер QR-кодів у Telegram або просто використання камери смартфона працівника (якщо QR-код містить deep-link на бота).
Логіка валідації: Працівник сканує код гостя. Бот миттєво видає один із 3 статусів:
✅ Успішно: Квиток дійсний, ліміт часу (до 20:00) не перевищено. Статус квитка в базі змінюється на "Використано" (повторно зайти за цим скріншотом неможливо).
❌ Помилка (Квиток вже використано): Виводиться час, коли код був погашений.
❌ Помилка (Час вийшов): Якщо на годиннику 20:01, бот повідомляє, що безкоштовний вхід закрито.
5. Функціонал для ролі "Адміністратор" (Бекенд/Адмінка)
Може бути реалізовано через приховані команди в самому боті або через окремий веб-інтерфейс.
Управління Guest List:
Встановлення ліміту на вечір (наприклад, 100 місць).
Можливість примусово закрити запис.
Система "Мертві душі": якщо код згенеровано, але не використано (гість не прийшов) 3 рази поспіль, система автоматично блокує цьому Telegram ID доступ до кнопки "Guest List" на 30 днів.
Обробка броні: Отримання сповіщень про нові заявки на столи в реальному часі (з номером телефону клієнта для швидкого дзвінка).
Редагування контенту: Можливість самостійно завантажувати нові картинки/тексти для "Афіші" та оновлювати "Меню" без залучення програміста.
Розсилка: Інструмент для масової відправки повідомлень (текст + картинка) всім зареєстрованим користувачам бази (або з фільтром: наприклад, тільки тим, хто хоч раз користувався Guest List).
6. Вимоги до технологій та безпеки
Мова програмування: Python (aiogram 3.x) або Node.js (Telegraf / grammY) — на вибір виконавця.
База даних: PostgreSQL або MySQL для надійного зберігання клієнтів, їхніх статусів та логів сканування квитків.
Безпека: Захист від накруток ботами (обмеження частоти запитів, прив'язка QR до конкретного акаунта і телефону). QR-код має містити зашифрований payload, а не просто порядковий номер.
Хостинг: Розгортання на хмарному сервері (VPS/VDS) з налаштуванням безперебійної роботи (наприклад, через Docker).
